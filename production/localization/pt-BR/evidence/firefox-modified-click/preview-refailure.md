# Native modified-click: final preview counterevidence

This addendum supersedes any interpretation that the `bringToFront()` change established parallel-suite stability. It does not erase the historical nine successful isolated repetitions.

Artifact: preview `/prompt-seen`, application build b8e0e7e392ff8fd259a8ef91aa40817de35bca75. The full multiworker suite recorded Firefox failure and retry failure of the unchanged native modified-click test at popup.browser.spec.ts:546, both timing out at context.waitForEvent(page), line 559. The new-tab document and no-JavaScript branches were not reached in those attempts.

Both traces show bringToFront completing successfully, the locator resolving the actual first card, and Meta-click completing normally. There is only one BrowserContext page event (the initial gallery) in each trace. The retained gallery URL stays `/prompt-seen/en/prompts/`. The elapsed interval from bringToFront completion to actual mouse-action dispatch is 243.039ms in the first attempt and 306.212ms in retry1, since locator resolution, actionability checks and scrolling happen between those actions.

This is consistent with another worker creating/activating a window after the foreground request and before the native modified-click. It is not proof: retained traces do not instrument OS foreground ownership or capture other workers’ window events. No exact Firefox internal cause has been established. A successful focus request cannot reserve the global foreground window until the subsequent click. Current evidence justifies neither weakening native page-event expectations nor changing application code.

Recommended validation execution: once the current suite finishes, execute this exact existing test across Chromium, Firefox and WebKit with `--workers=1`, `--repeat-each=3`, preserving all assertions and the no-JavaScript branch. Run other matrix cases with the exact title excluded, then run this title separately under `--workers=1`. Verify that their collected unique test IDs form a disjoint union equal to the original full suite (same browser project configuration); distinguish three unique browser cases from nine repeated executions. Record both invocations and all original failures. No skip, synthetic tab creation, expectation removal or extra retry-until-pass should be introduced.

Serial success would demonstrate isolated correctness under a controlled foreground environment, not establish that parallel native tests became reliable. A serial failure would require further diagnosis; do not keep rerunning until green.

Evidence: [trace event extraction](preview-refailure.json), including original archive SHA-256, absolute locations and monotonic timings; [initial error context](preview-initial-error-context.md), [retry error context](preview-retry1-error-context.md), and retained screenshots [initial](preview-initial-test-failed-1.png) / [retry](preview-retry1-test-failed-1.png). Original trace archives remain at the recorded artifact paths; the extraction preserves relevant raw events without duplicating 33 MB of bundles. No browser/service was launched and no product source/test file was modified for this addendum. The subsequent serial validation also failed once; see the [follow-up diagnosis](deep-diagnosis.md). The later bounded formal final-preview validation passed 9/9 without retries/skips; [formal result](final-preview-native-validation.json) closes preview acceptance while retaining this counterevidence and the unproved root cause.
