## 3. Prompt保存规则

每个案例建立三层记录，不能互相覆盖：

```text
production/gpt-image-26-social-2026-11-07/
  import-plan.json                 # 本次已生成：逐案例实施计划
  source-ledger.json               # 本次已生成：所有来源及待核实记录
  sources/<case>/source-prompt.txt # 执行阶段：作者原文完整提取
  sources/<case>/provenance.json   # 作者、链接、证据文件、提取边界、语言、哈希
  references/<ref>/prompt.txt      # 执行阶段：本项目新写的底图生成词
  references/<ref>/receipt.json
  jobs/<case>-<variant>/prompt.txt # 执行阶段：真正提交给模型的文本
  jobs/<case>-<variant>/definition.json
  recipes/<case>-<variant>.json
  audit/                          # 回执、参数、图片检查、合成链路
  content-map.json                 # 执行阶段：source→prompt→example→media映射
```

- 从保存的同帖正文/作者回复提取**完整原词**，不是从报告摘录补写。移除宣传语、回复称呼时保留提取位置；提示词内部段落、大小写、错别字、特殊符号、混合语言不修饰。
- 清单中的`source_excerpt`仅供辨认，不可作为完整生成输入。当前完整原词位置已定位，仍须逐条提取、检查截断和冻结哈希。
- G02/G08的表情主题、G10动作与字幕、S15猫眼选项、W01角色名称等可填参数，分别记录`source-prompt.txt`和`values.json`，提交文本保持原语言；不得偷偷加新的构图或安全风格指令后仍称逐字原词。
- 新底图提示词是本项目原创制作内容，按计划中指定语言另行编写。中文生成说明是执行简报，不冒充收集来的原提示词。
- 页面说明可翻译；新条目不生成Prompt译文，保证在中英文页面、复制、下载和导出中使用同一原语言正文。
- `promptProvenance: source-prompt`仅用于确为来源原词或明确填值的实例；若追加精灵图要求或重新编排指令，另存`independent-adaptation`条目。来源模型声明与本次真实模型回执分别保存，精确模型ID未知时为null。

## 6. 展示图片与GIF制作策略

### 静态图

优先直接按完整原词及必需输入生成。每个输出保留原始文件；使用现有媒体导入器生成card、detail、thumbnail、OG等派生尺寸。封面必须来自验收后的真实结果，不能拿来源图片充当本站生成结果。

### GIF

先执行小批能力验证：G13简单眨眼、G04播放一次、G16的12帧动作。记录模型实际返回的是PNG、精灵图还是多帧GIF，检查真实帧数、时长和loop。

- 通道可直接返回GIF：原词不改，保存真实GIF回执；静态展示图从真实GIF选代表帧提取，不重新生成一张不对应动画的“海报”。
- 通道只返回PNG：保留失败/非目标格式记录。需要原生原词实测的条目维持未完成；不能将PNG改扩展名，也不能把单帧复制多次伪装动画。
- 如需合成展示版本：用原语言另写精灵图或连续帧制作词，按任务要求编码GIF，并记录追加文字、帧裁切、时长和合成步骤。此版本独立标注为“同主题制作改编”，发布在独立改写条目；不为原词版本增加虚假的verified记录。原词版的实际完成数量单独计算。
- G04要求播放一次；其余是否循环按原词。不能统一套6帧或无限循环。
- G05中音乐请求无法由GIF容器承载，原词仍保留；验收说明明确静音和真实时长。若动作/镜头等关键要求也未实现，记为未达标，进入调整或待执行，不以“已生成文件”代替完成。
- 不将cocktailpeanut后续Minimax视频、thealexbanks后加音乐、createwithtimi的Rive重做结果记为GPT原生输出。

所有展示素材使用实际返回模型信息。若生成通道不能确认2.6，来源仍可以标“作者称使用2.6”，本站生成结果必须标实际已知模型/未知版本；不能因研究主题为2.6而伪造providerModelId。

## 7. 项目导入步骤

### 阶段A：来源、原词和输入冻结

1. 按`source-ledger.json`清点全部136条记录，15条回复归到对应案例，不重复创建内容卡。
2. 提取34条主案例及G03/G06子项的完整原词，保存原语言和来源哈希；核对主帖、回复、参考图与输出之间的对应关系。
3. 在计划里补齐每个实际任务的变体ID、输出数量、参考槽位与值；语义不同的原词分开编号。
4. 87条待核实线索逐条保留结论。补齐证据后可晋升实施清单；原词缺失时不根据图片猜一段文字冒充原词。像moltikuji、A5等模型未确认条目保持研究台账，不强行进入2.6实测合集。

完成条件：任何进入生成队列的任务都拥有完整Prompt、语言、来源、输入契约和真实可用的底图路径。

### 阶段B：底图生产与首批贯通

先生成R15、R16、R01，分别验证简单GIF、土耳其语输入与标注编辑；同时用S02完成无参考图静态任务。首批四个案例走完生成、视觉审核、prepare、apply、页面检查，再扩展到剩余任务。G04/G16随后确认GIF时序能力。

每个底图、成品任务使用独立key；同一key不覆盖输入和提示词。每个配方最多三次尝试，失败原因写明；改变输入或文本使用新key，不能自动无限重试。

### 阶段C：生成、验收、正式导入

沿用现有CLI，下面是参数模板，不是已执行日志；必须先有对应JSON及真实图片回执再运行：

```sh
npm run content:produce -- plan --campaign gpt-image-26-social-2026-11-07 --file <job.json>
npm run content:produce -- claim --campaign gpt-image-26-social-2026-11-07 --key <job-key>
# 使用claim返回的完整文本和有序图片调用生成工具，保存真实回执
npm run content:produce -- record --campaign gpt-image-26-social-2026-11-07 --key <job-key> --file <receipt.json>
npm run content:produce -- review --campaign gpt-image-26-social-2026-11-07 --key <job-key> --file <review.json>
npm run content:produce -- recipe-hash --file <recipe.json>
# 核对文案后，将哈希加入editorialReview
npm run content:produce -- prepare --campaign gpt-image-26-social-2026-11-07 --key <job-key> --file <recipe.json>
npm run content:produce -- apply --key <job-key> --hash <prepare返回的哈希>
```

`content:produce`不调用图片模型，必须由生成步骤提供真实输出。ID由prepare/apply按当前内容状态分配，写入`content-map.json`；不能预留一段固定p/x/a编号后并行写入。生成可分批，正式导入串行。

配方要求：`promptLanguage`为en/ja/zh-Hans/tr；`body`与实际生成文本完全匹配；参考图为真实本地输入；标题、说明、alt中英双语；`inspirationSources`保存原帖指标及证据等级；新图本身不拥有来源帖点赞。合成改写和原词实测不得共用同一身份标记。

对于保留原始方括号或大写占位符的来源模板，先冻结未改原文，再保存填写后的原语言字面样例和values映射，不为迁就内部字段命名直接改写源文件。是否进一步做可交互模板作为后续独立版本；本批以可复制、可追溯的已填样例为主。

### 阶段D：合集与展示接入

创建`gpt-image-26-social-original-prompts`总合集，说明是多语种社交来源的本站实测。静态、GIF和工作流分组；来源互动排序采用日期明确的X快照，Reddit独立显示。只有实际验收导入的条目进入合集，数量动态取真实条目数。

## 8. 验收与完成标准

- **原语言**：日语、土耳其语条目在中英文界面显示/复制/下载/导出保持原文；混合语言变量不丢失，长文本不被截断。
- **输入可复现**：所有required槽位都有对应生成底图及回执，run中的顺序和文件哈希一致；用户能看到应准备的图片及用途。
- **输出一致**：页面展示图与记录Prompt和输入来自同一次真实生成；封面来自该次结果，不能跨案例借图。
- **GIF真实**：多帧有实际姿态差异、指定文字稳定、动作完整、播放次数和时长符合记录；透明图在深浅底上检查边缘。目标与实测不符时记录失败或局限，不能篡改原词掩盖差异。
- **来源语义**：作者归属、原词链接、指标日期正确；对比帖和工作流的整帖热度有说明，不用aggregateRating表示点赞。
- **旧内容兼容**：现有条目继续可用；p_221/p_228的历史输出与文本不变，新原词版可追溯到同一来源。
- **覆盖率真实**：34条主案例逐条记录accepted/blocked/deferred；39条正文单元、42个成品是目标，未达标不能称为全部完成。87条待核实记录必须有处置状态，但不以创建空目录当作导入。
